## ۱. آموزش — اندازه‌گیری واقعی در مرورگر

| بررسی | مقدار اندازه‌گیری‌شده |
|---|---|
| مساحت کارت روی ۸۴۴×۳۹۰ | ۳۰۰×۱۳۷ CSS px = **۱۲٫۵٪** صفحه |
| هم‌پوشانی کارت با هدف (دکمهٔ خدمه) | **۰ px²** |
| هم‌پوشانی کارت با نوار پایین | **۰ px²** |
| اسپات‌لایت روی هدف | بله؛ اندازه‌گیری هم‌پوشانی > ۰ |
| تیره‌سازی پس‌زمینه | ۴۰٪ (قبلاً ۵۵–۶۲٪ و روی همه‌چیز) |
| پیشروی با اقدام واقعی | بله — کلیک روی «خدمه» گام را جلو برد |
| کوچک‌کردن / رد کردن / ادامه پس از ریلود | تست Playwright، ۲ سناریو، سبز |
| تست خودکار مساحت و عدم برخورد | `tests/e2e/tutorial.spec.ts` |

روش: مرورگر واقعی Edge با `deviceScaleFactor: 2`، `hasTouch: true`؛ ابعاد از
`getBoundingClientRect` خوانده شد، نه از تصور.

## ۲. منوی اصلی

- نقاشی شناور کامل (بدنه، برج فرمان، دکل، پنجره‌های روشن، نورافکن، ملخ، آشیانهٔ ROV).
- پرتوهای نور متحرک، برف دریایی، چراغ‌های چشمک‌زن با CSS.
- گزینه‌های واقعی: ادامه، شروع کمپین، بقا، مأموریت‌ها، راهنمای فرمانده، تنظیمات، درباره سازنده.
- «درباره سازنده» شامل امین، تلگرام @Mozrd، روبیکا @angosht0 و نسخهٔ بازی.

## ۴. پیاده‌شده ولی تست‌نشده روی گوشی

- لمس واقعی کارت شناور و اسپات‌لایت در WebView.
- چیدمان منو روی نمایشگرهای با نوار وضعیت بلند.
- مصرف CPU در جلسهٔ طولانی با کارت فعال.

## ۵. باگ‌های شناخته‌شده

1. اگر هدف در یک شیت باز باشد، کارت ممکن است در گوشهٔ صفحه قرار بگیرد (مکان‌یابی، نه هم‌پوشانی).
2. نقاشی منو تصویر ثابت است؛ تنها پرتو و ذرات CSS حرکت می‌کنند.
3. آموزش هنوز ۱۲ گام است؛ گام‌های ۶، ۸ و ۱۰ به وضعیت واقعی شبیه‌سازی وابسته‌اند و اگر بازیکن خودش زودتر انجام دهد، درست جلو می‌رود ولی ممکن است یک گام «انجام دادم» لازم شود.
4. صدا فقط درون‌مایهٔ تولیدی است، نه موسیقی دارای مجوز.

## ۶. کار باقی‌مانده برای استاندارد کامل V4

- اطلس هنری دارای مجوز و بازسازی تجهیزات با اسپرایت.
- صحنهٔ تعاملی ROV، روایت کمپین، کدکس.
- موسیقی چندلایه و افکت‌های واقعی.
- بهینه‌سازی باندل (Phaser جدا) و بارگذاری تنبل پنل‌ها.
